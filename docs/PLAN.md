# برنامه و معیار پذیرش

اندازه‌ها برآورد نسبی‌اند، نه زمان تحویل. ریسک با یافته‌های جدید اصلاح می‌شود.

| شناسه | برش | اندازه / ریسک | پذیرش |
|---|---|---|---|
| P0 | مخزن عمومی با تأیید کاربر و اسناد | کوچک / دسترسی | وجود مخزن و visibility=public تأیید شود |
| P1 | runtime، صحنه، restart، ورودی | متوسط / دستگاه | کنترل و آزادشدن ورودی پس از قطع فوکوس؛ نسخهٔ قابل‌تست |
| P2 | یک قهرمان melee و dummy | متوسط / timing | startup/active/recovery و dodge قابل‌مشاهده و آزمودنی |
| P3 | دشمن پاسخ‌گو و ranged kit | متوسط / بالانس | melee امکان نزدیک‌شدن با ریسک معنادار داشته باشد |
| P4 | Action Sequence | متوسط / عدالت ورودی | هیچ cooldown یا هزینه‌ای دور زده نشود؛ مقایسه با اجرای دستی |
| P5 | دو بازیکن شبکه‌ای | بزرگ / تأخیر | رفتار در پینگ و jitter ثبت شود؛ نیاز سرور با تصمیم وب روشن شود |
| P6 | هدف تیمی و یک فرمان RTS | بزرگ / پیچیدگی کنترل | بدون از دست رفتن کنترل اکشن، تصمیم استراتژیک معنادار ایجاد کند |

برای هر برش: نیاز → معیار پذیرش → commit منسجم → تست لازم → گزارش قبل/بعد → تصمیم. تست نمایشی برای تغییر کم‌خطر لازم نیست. هر تغییر آزمایشی با build و پارامترها قابل‌ردیابی باشد. baseline عملکرد گوشی هدف پس از P1 اندازه‌گیری شود؛ اکنون هیچ FPS یا latency گزارش‌شده‌ای وجود ندارد.
