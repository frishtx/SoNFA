# برنامه و معیار پذیرش
اندازه‌ها برآورد نسبی‌اند، نه زمان تحویل. ریسک با یافته‌های جدید اصلاح می‌شود.
برنامهٔ جهان و تولید در [نشست استودیو](studio/SESSION.md)؛ این صفحه مسیر فنی موجود را حفظ می‌کند.

- P0 — مخزن عمومی و اسناد؛ کوچک / ریسک دسترسی. پذیرش: وجود مخزن و عمومی‌بودن آن تأیید شود.
- P1 — runtime، صحنه، restart و ورودی؛ متوسط / ریسک دستگاه. پذیرش: کنترل و آزادشدن ورودی پس از قطع فوکوس؛ نسخهٔ قابل‌تست.
- P2 — یک قهرمان melee و dummy؛ متوسط / ریسک timing. پذیرش: startup/active/recovery و dodge قابل‌مشاهده و آزمودنی.
- P3 — دشمن پاسخ‌گو و ranged kit؛ متوسط / ریسک بالانس. پذیرش: melee امکان نزدیک‌شدن با ریسک معنادار داشته باشد.
- P4 — Action Sequence؛ متوسط / ریسک عدالت ورودی. پذیرش: هیچ cooldown یا هزینه دور زده نشود؛ مقایسه با اجرای دستی.
- P5 — دو بازیکن شبکه‌ای؛ بزرگ / ریسک تأخیر. پذیرش: رفتار در پینگ و jitter ثبت شود؛ نیاز سرور با تصمیم وب روشن شود.
- P6 — هدف تیمی و یک فرمان RTS؛ بزرگ / ریسک پیچیدگی کنترل. پذیرش: تصمیم استراتژیک معنادار بدون از دست رفتن کنترل اکشن.

برای هر برش: نیاز، معیار پذیرش، commit منسجم، بررسی لازم، گزارش و تصمیم.
تست نمایشی برای تغییر کم‌خطر لازم نیست. هر تغییر آزمایشی با build و پارامترها قابل‌ردیابی باشد.
baseline عملکرد گوشی هدف پس از P1 اندازه‌گیری شود؛ اکنون FPS یا latency گزارش‌شده‌ای وجود ندارد.
